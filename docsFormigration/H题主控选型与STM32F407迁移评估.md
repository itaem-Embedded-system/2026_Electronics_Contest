# H题主控选型与STM32F407迁移评估

## 1. 结论摘要

### 1.1 当前 MSPM0G3507 是否够用

够用。

当前工程的主控只通过 UART1 接收视觉模块输出的钢球偏移值 `x_offset\n`。因此，主控的核心负载是：

- 灰度循迹采样，周期 10 ms。
- 底盘速度环、转向环、位置环与循迹策略，周期 50 ms。
- 题目 3 的视觉位置滤波、速度估计、PD 控制和 ZDT 串口位置命令，周期 20 ms。
- OLED、按键、蜂鸣器和系统监控等低频任务。

MSPM0G3507 的 80 MHz Cortex-M0+、128 KB Flash、32 KB SRAM 对这类坐标输入型控制任务可以胜任。当前代码的主要缺口不是 CPU 算力，而是题目功能尚未完整实现，以及实车标定和机械动态尚未闭环验证。

### 1.2 是否建议迁移到 STM32F407VET6

如果现有 MSPM0 板已稳定运行且比赛周期紧，建议优先保留当前板，先完成题目 2、题目 3 和实车标定。

如果准备将主控板更换为 STM32F407VET6 最小系统板，并计划继续实现题目 4、题目 5、题目 6 的行驶稳球、前馈补偿、更多调试记录或更高控制频率，STM32F407VET6 是合理的升级目标。它能显著增加浮点运算、内存、DMA、硬件编码器和外设余量。

但换成 F407 不会自动解决以下问题：

- UART 115200 bit/s 的物理线速。
- ZDT 闭环步进电机的串口协议延迟、速度、加速度和机械间隙。
- 摆杆摩擦、钢球滚动非线性、车身加速度和过弯扰动。
- 赛道、停车线、循迹器安装和电源噪声带来的实车问题。

因此，F407 是提高控制系统余量和可扩展性的手段，不是替代控制建模与实车标定的方案。

## 2. 当前工程的硬件资源需求

### 2.1 已实际配置的外设

下表来自当前 `empty.syscfg` 和用户驱动代码。当前构建启用灰度、OLED 和 ZDT；IMU、超声波、蓝牙和 VOFA 输出默认关闭。

| 左右编码器 | 左右 A 相中断，B 相判向 | 4 路数字输入 | 优先使用两个定时器的编码器模式，直接采集 AB 相。 |
| 八路循迹 | 8 路数字 GPIO | 8 路输入 | 普通 GPIO 读取即可，也可使用 DMA/定时器触发采样做诊断。 |

| ZDT 摆杆电机 | UART0，115200 bit/s | 1 路 UART TX/RX | 使用 USART 和 DMA/中断队列，避免控制任务阻塞等待发送完成。 |

| IMU | SPI、CS、数据就绪中断 | 1 路 SPI + 2 GPIO | 若启用，使用 SPI DMA 或中断方式读取；不把浮点姿态解算放进 ISR。 |
| 蜂鸣器/LED | GPIO 输出 | 2 路输出 | 普通 GPIO。 |

### 2.2 当前控制周期与负载

| 任务 | 当前周期 | 主要计算 | 对 CPU 的要求 |
|---|---:|---|---|
| `GrayTask` | 10 ms | 8 路采样、加权误差、停止线锁存 | 很低 |
| `Ctrl_Task` | 50 ms | 编码器测速、位置环、循迹、两组 PID、PWM 合成 | 低到中等 |
| `ZDT_Test` | 20 ms | 视觉快照、低通、速度估计、PD、卡死突破、串口命令 | 中等，主要受串口阻塞影响 |
| `OLED_Task` | 20 ms | 菜单、秒表、全屏软件 I2C 刷新 | CPU 占用可能高于算法本身 |
| 可选 `IMU_Task` | 数据就绪触发 | SPI 读数、Mahony 姿态解算 | M0+ 上的浮点代价较高 |

当前不做图像处理、不做 FFT、不做复杂路径规划，也没有 1 kHz 以上的电机电流环。因此，主控性能不是现有任务的首要瓶颈。

## 3. 两种主控对比

| 项目 | MSPM0G3507 | STM32F407VET6 | 对本项目的意义 |
|---|---|---|---|
| CPU | Arm Cortex-M0+，80 MHz | Arm Cortex-M4F，最高 168 MHz | F407 的通用算力和指令效率更高。 |
| 浮点能力 | 无通用硬件单精度 FPU，浮点大多为软件实现 | 单精度 FPU，带 DSP 指令 | F407 更适合更高频的 PD/PID、滤波、姿态融合和前馈计算。 |
| Flash | 128 KB | 512 KB | F407 更适合保存更完整的协议、日志、诊断和扩展功能。 |
| SRAM | 32 KB | 192 KB | F407 可容纳 DMA 缓冲、串口环形队列、日志和更大的 RTOS 任务栈余量。 |
| UART | 4 路 | 最多 6 路 USART/UART | 两者均满足当前至少 3 路串口需求，F407 更有扩展余量。 |
| SPI/I2C | 2 SPI、2 I2C | 3 SPI、3 I2C | 两者满足当前 IMU/OLED，F407 更适合改为硬件 I2C 和 DMA。 |
| 定时器和编码器 | 通用定时器充足，含 TimerG QEI；当前工程用 GPIO ISR 解码 | 多个高级/通用定时器，原生增量编码器模式 | F407 可显著改善编码器采样实现，减少 ISR 负担；但 MSPM0 的 TimerG QEI 也能硬件解码，编码器并非换主控的决定性理由。 |
| DMA | 支持 DMA | 双 DMA、流和 FIFO，外设生态成熟 | F407 更方便将 UART、SPI、I2C 等通信从任务周期中剥离。 |
| ADC/DAC | 2 组 4 MSPS ADC、DAC、比较器、运放 | 3 组 12 bit ADC、2 DAC | 当前项目几乎不依赖 ADC；MSPM0 的模拟外设并不是短板。 |
| 调试与开发 | CCS Theia、SysConfig、TI DriverLib | STM32CubeMX/CubeIDE、HAL/LL、ST-Link | F407 生态更常见，但迁移必须重建底层。 |

规格来源：TI MSPM0G3507 官方产品页和数据手册；ST STM32F407VE 官方产品页和数据手册。具体引脚、封装、复用和电气参数必须以最终采购芯片的最新数据手册为准。

## 4. MSPM0G3507 的适配度判断

### 4.1 已实现和计划中的功能

| 目标 | MSPM0G3507 是否足够 | 原因 |
|---|---|---|
| 题目 2 单圈循迹、停车、计时 | 足够 | 10 ms 灰度采样和 50 ms PID 负载很低。 |
| 题目 3 静止滚球 | 足够 | 视觉模块只给坐标，20 ms 的位置/速度滤波和 PD 计算量有限。 |
| 题目 3 O 到 +5 cm 再到 -5 cm | 足够 | 缺的是目标状态机、标定和机械调参，不是处理器算力。 |
| 题目 4/5 行驶中稳球 | 原则上足够，但余量偏紧 | 需要增加速度、加速度、转向扰动补偿。现有 M0+ 可做基础前馈，但软件浮点和通信阻塞会压缩余量。 |
| 题目 6 任意点保持 | 足够 | 缺的是车载输入方式、目标映射和状态管理。 |

### 4.2 当前更值得优先处理的瓶颈

1. **ZDT 串口阻塞发送**：当前位置命令为 13 字节，代码以轮询方式发送。即使 F407 更快，若仍以相同 115200 bit/s 和同步发送方式运行，通信时延不会消失。
2. **视觉数据链路**：当前只有“最新整数偏移值”和 ready 标志。视觉帧率、抖动、延迟、坐标比例与丢帧策略对滚球控制比主频更敏感。
3. **摆杆机构**：步进电机行程、速度、加速度、间隙、摩擦和重力模型决定控制上限。卡死突破只能缓解局部静摩擦，不能替代机械优化。
4. **软件 I2C 全屏 OLED 刷新**：当前每 20 ms 刷新 1024 字节屏幕，软件翻转 GPIO 会占用 CPU。可以先降低刷新率或改硬件 I2C。
5. **编码器实现**：当前只在 A 相上升沿计数、读取 B 相判向。速度低时分辨率有限，高速时 ISR 抖动也会影响测量。F407 的硬件编码器模式有明确优势，但 MSPM0 本身也可改用 TimerG QEI 硬件解码（详见 4.3），编码器并非换主控的决定性理由。
6. **RTOS 内存余量**：当前 FreeRTOS 动态堆为 25 KB，芯片总 SRAM 只有 32 KB。现有 `CPU_Monitor` 可观察剩余堆和栈高水位，应在实车最坏负载下记录数据后再判断是否真的需要扩容。

### 4.3 编码器能力澄清与迁移影响

F407 的 TIM Encoder Mode 与 MSPM0 的 QEI 本质上是同一类外设，都能硬件完成 AB 相正交解码、计数器自动加减、方向位以及可选 x1/x2/x4 解码倍频，不需要每个编码器脉冲进入 ISR。F407 并不是“没有 QEI”，只是把该功能命名为“定时器编码器接口模式”（Timer Encoder Mode），而不是独立命名的 QEI 外设。

两者的速度计算方式本质相同：硬件负责位置计数和方向，软件按固定周期读取两次计数器后做差分：

$$
\Delta N = N_k - N_{k-1}
$$

$$
v = \frac{\Delta N}{N_{\text{wheel}} \, T_s} \cdot 2\pi r
$$

其中 $N_{\text{wheel}}$ 是车轮转一圈对应的总计数，包含编码器线数、减速比和解码倍频。

| 能力 | MSPM0 QEI | F407 Encoder Mode |
|---|---|---|
| 硬件 AB 解码 | 有 | 有 |
| 硬件方向 | 有 | 有 |
| 硬件位置计数 | 有 | 有 |
| 直接给 cm/s、rpm | 没有 | 没有 |
| 软件差分求速度 | 需要 | 需要 |
| Z 相 Index | 原生支持更方便 | 需用 EXTI/ETR 等额外配置 |
| 非法相位跳变检测 | 部分 QEI 实例支持 | 无专用 QEI 错误标志 |
| 32 位计数器 | 需看具体 TimerG | TIM2/TIM5 可用，较方便 |

在 F407 上落地时的定时器选择要点：

- **主编码器优先用 TIM2**：可作为 32 位编码器计数器，适合长时间自由运行的累计计数。
- **第二路备用定时器**：若因引脚冲突无法使用 TIM5，可改用 TIM3 或 TIM4 的编码器模式。
- **16 位定时器不必每次清零**：采用周期读取 CNT 并做差分即可。
- **回卷保护**：对 16 位计数器，必须保证采样周期内的计数增量小于 32768，否则会出现回卷判错。
- **软件累计位置**：软件位置量用累计变量保存，硬件 CNT 只负责原始脉冲计数；差分与累计在任务中完成。

当前 `encoder.c` 实际是 A 相 GPIO 中断、B 相判向，`empty.syscfg` 也没有配置 QEI。因此，如果当前编码器引脚能重新映射到两个支持 QEI 的 TimerG 通道，MSPM0 本身就可以改成硬件 QEI，不必为编码器功能单独换 F407。

迁移成 QEI 后必须重新标定以下参数，因为硬件 QEI 的计数倍频可能比当前“A 相单上升沿计数”高 2 倍或 4 倍：

- `MAX_PULSE_50MS`
- `POSITION_PULSE_PER_CM`
- 左右轮速度比例
- PID 参数
- 方向符号

## 5. STM32F407VET6 方案结论与边界

STM32F407VET6 的算力、FPU、Flash、SRAM、定时器、串口和 DMA 资源对本题均有充分余量。最直接的收益不是单纯提高主频，而是用硬件外设降低控制链路的不确定性：

- 两路编码器由定时器硬件完成 AB 正交解码，替代 GPIO 边沿中断。
- UART、SPI 和 I2C 可使用 DMA 或中断队列，减少通信阻塞。
- FPU 和更大的 SRAM 适合姿态融合、前馈补偿、日志和串口缓存。
- 题目 2~6 的控制任务不构成 F407 的算力瓶颈。

F407 仍不能替代视觉零位/比例标定、编码器脉冲标定、摆杆机构调试和实车验证；115200 bit/s 的物理传输时间也不会因换主控而消失。

## 6. 编码器优先方案与外设分配

### 6.1 本扩展板的首要配置：TIM2 + TIM3 Encoder Mode

根据 `Netlist_PCB7_2026-09-03.tel`，本板为两个直流减速电机各提供一组 AB 编码器输入，四根信号线均配置了 `100 Ω` 串联电阻和 `100 pF` 对地电容：

| 电机编码器 | MCU 引脚 | 定时器复用 | RC 网络 |
|---|---|---|---|
| 编码器 1 | `PA0 / PA1` | `TIM2_CH1 / TIM2_CH2` | `R17/C13`、`R16/C14` |
| 编码器 2 | `PC6 / PB5` | `TIM3_CH1 / TIM3_CH2` | `R6/C8`、`R7/C7` |

网表中的 `PD12/PD13`、`PE9/PE11` 不纳入当前两电机编码器方案，保留为扩展或备用信号。`NRST`、`BOOT0`、`SWDIO`、`SWCLK`、`VSSA`、`VDDA`、外部晶振、调试串口和复位按键由 F407 最小系统板提供，本扩展板无需重复设计。

CubeMX 优先配置：

- `TIM2 Encoder Mode`：`PA0=CH1`、`PA1=CH2`，使用 32 位计数器。
- `TIM3 Encoder Mode`：`PC6=CH1`、`PB5=CH2`，使用 16 位计数器。
- 编码器模式先选 `TI1 and TI2`、预分频 `0`、上升沿；数字滤波从较小值开始，避免与外部 RC 叠加后漏计数。
- 启动后先验证单轮计数、正反转方向和 A/B 相对应关系，再接入速度 PID。

硬件 Encoder Mode 只负责计数和方向，速度仍需由固定周期差分计算：

```text
count_delta = count_now - count_last
speed = count_delta / (wheel_counts_per_rev * sample_period)
```

`TIM2` 可长期自由运行；`TIM3` 采用带符号差分处理 16 位回卷。迁移后必须重新标定解码倍频、`MAX_PULSE_50MS`、`POSITION_PULSE_PER_CM`、左右方向符号和 PID 参数。

### 6.2 其他外设安排

| 功能 | 建议资源 |
|---|---|
| 左右 H 桥 PWM | 避开 TIM2/TIM3 CH1/CH2，使用其他可用定时器通道 |
| 视觉串口 | USART RX DMA 环形缓冲，保留最新完整帧 |
| ZDT 串口 | USART TX/RX DMA 或非阻塞发送队列 |
| 调试串口 | 独立 USART，正式测试关闭高频输出 |
| OLED | 硬件 I2C；显示刷新与控制周期解耦 |
| IMU | SPI + DMA 或数据就绪中断 |
| 灰度、按键、蜂鸣器、LED | 普通 GPIO，使用定时任务采样或更新 |
| RTOS 节拍 | SysTick 或独立定时器 |

## 7. 软件迁移边界与关键注意事项

可复用的是控制算法、题目状态机、视觉数据处理顺序、ZDT 协议和视觉 ASCII 协议；必须重写的是启动及时钟、GPIO、PWM、定时器、UART、SPI、I2C、NVIC、编码器底层、链接脚本和 FreeRTOS 配置。

迁移时重点注意：

- F407 使用 Cortex-M4F 对应的 FreeRTOS 端口和浮点编译选项，确认任务切换能正确保存浮点上下文。
- 重新设置中断优先级，调用 FreeRTOS `FromISR` API 的中断必须满足新的 `configMAX_SYSCALL_INTERRUPT_PRIORITY` 规则。
- DMA 缓冲区放在普通 SRAM，不要默认放入 DMA 不可访问的 CCM RAM。
- PWM 不得占用 `TIM2/TIM3` 的编码器通道；上电必须保持 PWM 关闭。

## 8. 最小可行迁移顺序

1. **编码器验证**：CubeMX 生成 `TIM2 + TIM3 Encoder Mode`，确认两组 AB 输入、方向、计数倍频和 50 ms 差分。
2. **底盘闭环**：迁移 PWM、速度采样和急停，完成轮速/距离标定，再接入速度环和转向环。
3. **循迹功能**：迁移八路灰度、按键、蜂鸣器和 OLED，先复现题目 2。
4. **通信与摆杆**：迁移视觉 UART 和 ZDT UART，先验证协议、绝对位置和丢帧处理，再接入题目 3。
5. **功能完善**：实现题目 3 的 `O→+5 cm→-5 cm`，再扩展题目 4/5 行驶稳球和题目 6 指定位置保持。

每一步都要进行实车验证。MSPM0G3507 保留为基线，至少在 F407 完成编码器、底盘和题目 3 的等效验证前，不应直接弃用原板。

## 9. 最终建议

将 STM32F407 扩展板的第一优先级明确为：

> **先完成 `TIM2 + TIM3` 硬件 Encoder Mode，再围绕计数器差分建立可靠的轮速和位置反馈。**

本题使用 F407 在资源上是充足的，后续扩展不受 CPU、内存或定时器数量限制。真正需要控制风险的是引脚复用确认、编码器方向/倍频/脉冲比例标定、PWM 定时器避让，以及通信和机械系统的实车表现。
